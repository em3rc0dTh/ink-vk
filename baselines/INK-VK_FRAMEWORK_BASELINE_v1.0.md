> **Chinese Method finds the DNA. Ink makes it belong. VK verifies the transformation.**

## 1. Baseline decision

STEP 0 — FOUNDATION is frozen at v1.0.

This baseline means Ink-VK is now sufficiently specified to open and operate a new Chinese Method transformation without reconstructing the method from previous conversations.

It does **not** mean the framework can never change.

Future evidence produces versioned deltas:

```text
v1.0
  ↓
v1.1 / v1.x
  ↓
v2.0 when foundational contracts materially change
```

Historical artifacts remain preserved.

## 2. Definition

Ink-VK is a controlled source-to-soul engineering framework.

It:

```text
recovers a target
understands what must survive
mines proven external intelligence
dissects donor jobs and DNA
declares intended fidelity
filters donor intelligence through target truth and Soul
re-authors the result as a target-owned system
implements under controlled contracts
validates fidelity, truth, non-regression, provenance, and ownership
records what the next case can reuse
```

Ink-VK is not a license to copy proprietary code, assets, text, or identity.

Public availability does not imply reuse permission.

## 4. Replication modes

```text

R2 — STRUCTURAL TRANSPOSITION

```

A case may use different modes by layer.

Direct code/asset reuse belongs to R4 and requires authorization/provenance evidence.

Authority:

`methodology/INK-VK_REPLICATION_MODES_v0.1.md`

The mode model is adopted operationally by this v1.0 baseline even though empirical depth remains uneven across modes.

## 5. Target authorities

Before donor transformation, the target must have sufficient control in four dimensions:

```text
TARGET RECOVERY
TARGET NON-REGRESSION
TARGET SOUL
TARGET TRUTH
```

### Target Recovery

What exists.

### Target Non-Regression

What known failure must not return and what positive control must survive.

### Target Soul

What makes the transformed result belong to this target in mission, worldview, operational reality, relationship model, voice, trust, symbols, and constraints.

### Target Truth

What the target is actually allowed to claim, render, activate, or imply.

## 6. Truth extension gates

Apply when relevant:

### Content Capacity

```text
C0 — no supported content
C1 — single record/state
C2 — peer set
C3 — classifiable library
C4 — deep multi-state system
```

Rule:

> **Design for future capacity; render current truth.**

### Institutional Evidence Scope

Narrative identity does not prove people, partner, quantitative, or active institutional depth.

### Interaction Dependency Truth

```text
D0 — presentation/schema only
D1 — local interactive state
D2 — validated local state
D3 — submission/transport
D4 — delivery/persistence/integration
D5 — acknowledged downstream outcome
```

Rule:

> **Transfer interaction choreography only up to the highest target dependency state actually supported.**

## 7. Mining / quarry model

External sources are organized as mining sites and quarries.

A quarry is evidence, not automatically a donor.

Source roles:

```text
PRIMARY DONOR
SECONDARY DONOR
PATTERN SOURCE
REFERENCE ONLY
REJECTED SOURCE
```

Each serious source preserves provenance, observed evidence, transfer value, risks, and rights boundary.

## 8. Donor dissection rule

Match donor jobs, not donor pages as indivisible blocks.

A donor page/module may contain:

```text
orientation
decision
comparison
proof
process
trust
FAQ
navigation/disclosure
conversion
status
continuity
```

Each job may receive an independent disposition.

## 9. DNA rule

Donor expression and donor DNA are different artifacts.

A useful DNA record identifies:

```text
pattern
observed evidence
job
why it works
transfer conditions
non-transferable expression
risks
confidence
```

A donor-specific visual object, brand motif, copy block, or proprietary asset is not automatically DNA.

## 11. Ink rule

Ink is the re-authorship layer.

It may change:

```text
meaning
terminology
visual semantics
interaction meaning
workflow
states
architecture
data / ownership boundaries
proof
trust mechanisms
symbols
motion semantics
```

Ink passes when the transformed decision is justified by target reality rather than donor preference alone.

## 12. Coherence rule

Multi-route/module targets require:

```text
ONE GOVERNING SYSTEM
+
PURPOSE-SPECIFIC PAGE / MODULE MODES
```

Coherence is not one universal template.

Strong signature devices must have semantic ownership.

## 13. Concept-frame authority

Rendered frames, mockups, and screenshots are evidence, not automatically the strongest implementation authority.

When a concept frame conflicts with a frozen semantic blueprint:

```text
FROZEN CONTRACT / BLUEPRINT
        >
SCREENSHOT LITERALISM
```

unless a later explicit design decision supersedes the blueprint.

## 14. Design Freeze / unknown rule

Remaining unknowns are classified:

```text
FROZEN
BOUNDED / IMPLEMENTATION-SAFE
DEFERRED / OPTIONAL DEPENDENCY
BLOCKING UNKNOWN
```

PLAN requires:

```text
BLOCKING UNKNOWN = 0
```

The framework does not require false precision for implementation-safe calibration.

## 15. BUILD authority

BUILD is authorized only by:

```text
TARGET TRUTH
+
TRANSFORMATION CONTRACT
+
INK SPECIFICATION
+
FROZEN BLUEPRINT
+
PLAN
```

The donor is not direct BUILD authority unless R4 explicitly authorizes implementation reuse.

## 16. Validation stack

A complete implementation runs:

```text
DONOR PARITY
SOUL INTEGRITY
TARGET TRUTH / CLAIM / DEPENDENCY
TARGET NON-REGRESSION
MODE-AWARE VK
```

A pass in one dimension cannot excuse failure in another.

## 17. Evidence discipline

Use:

```text
OBSERVED
INFERRED
UNKNOWN
DECIDED
DEFERRED
```

Where useful:

```text
Q0 — raw capture / direct artifact
Q1 — live source / runtime
Q2 — extracted system
Q3 — recovered topology
Q4 — interpretation
```

Interpretation never silently becomes raw evidence.

## 18. Knowledge governance

Ink-VK is append-only in meaning.

- frozen baselines are not silently rewritten;
- valid older versions remain history;
- `deprecated/` is reserved for explicitly invalidated directions;
- provenance and decision lineage must remain recoverable from the repository.
