**Status:** PROPOSED / FOUNDATION ITERATION  
**Date:** 2026-08-14  
**Supersedes conceptually:** `INK-VK_MIGRATION_FLOW_v0.2.md`; historical versions remain preserved.  
**New learning source:** VTKALL Home × Dayos section-by-section transformation

---

# 1. Why v0.3 exists

v0.2 introduced replication modes and correctly allowed a case to seek high donor similarity.

The VTKALL × Dayos Home pass exposed the next missing control:

> A donor can define a section, route, interaction, proof slot, metric row, plan selector, partner block, or 3D role without proving that the target has the business truth required to populate it.

Without a separate truth gate, high-fidelity work can silently become:

```text
DONOR STRUCTURE
+
INVENTED TARGET ANALOGUES
```

v0.3 therefore adds:

```text
TARGET TRUTH BASELINE
+
SLOT-LEVEL TARGET TRUTH CHECK
```

The new governing phrase is:

> **Structural parity under target truth.**

# 3. STEP 04 — FREEZE TARGET TRUTH BASELINE

This is the major addition.

The Soul says what the target **is** and what must not be erased.

The Truth Baseline says what the project is currently allowed to assert, structure, demonstrate, compare, or sell publicly.

These are not the same thing.

Example:

```text
SOUL
VertikALL values long-term ally relationships.

TRUTH BASELINE
No formal public Partnership program/process is currently established.
```

Therefore:

```text
ALLY PHILOSOPHY      → VALID
PARTNERSHIP ROUTE    → NOT AUTOMATICALLY VALID
PARTNER TIERS        → UNSUPPORTED
PARTNER METRICS      → UNSUPPORTED
```

The Truth Baseline records:

```text
known products
known services
known capabilities
known demonstrations
known production systems
known customers
known relationships
known routes/content
known proof
known pricing
known commercial process
approved future decisions
unknowns
claim ceilings
```

Output:

```text
TARGET TRUTH BASELINE
```

A target artifact may contain several classes simultaneously.

The classification must survive into design and copy decisions.

```text

```

The mapping is still exploratory.

It does not admit the donor slot yet.

# 6. STEP 13 — ROUTE / SLOT TARGET-TRUTH GATE

Every proposed donor-derived unit must now be admitted explicitly.

Unit may be:

```text
route
section
component
CTA
proof slot
metric
comparison
plan/pricing block
partner/customer block
form field
3D semantic object
interaction disclosure
```

For each unit ask:

```text
1. What is the donor information job?
2. What is the target information job?
3. What target evidence supports it?
4. What is the evidence class?
5. What is the public claim ceiling?
6. Is there enough target content to make the unit coherent?
7. Does the target actually have the state the interaction controls?
8. Is proof available if the donor slot requires proof?
```

Then choose:

```text
FILL
REFRAME
OMIT
DEFER
```

There is no `INVENT` option.

Output:

```text
ROUTE / SECTION / SLOT TRUTH CONTRACT
```

# 7. Route admission rule

A donor route may enter the target topology only when:

```text
TARGET INFORMATION JOB EXISTS
+
SUFFICIENT TARGET CONTENT EXISTS
+
CLAIM CEILING IS KNOWN
+
ROUTE IS NOT DONOR-ONLY DECORATION
```

Example learned from VTKALL:

```text
DAYOS PARTNERSHIP
```

has a strong donor page mode.

VertikALL has an ally/harbor philosophy.

But current evidence does not establish:

```text
formal partner program
partner application model
pilot relationship contract
partner tiers
partner metrics
```

Therefore the current correct disposition is:

```text
PARTNERSHIP ROUTE → OMIT
ALLY PHILOSOPHY   → KEEP IN TARGET NARRATIVE
```

# 9. Interaction truth rule

An interaction can only be replicated when the target has the state/content the interaction manipulates.

Examples:

```text
DONOR DROPDOWN EXISTS
+
TARGET HAS NO VALID CHILD ROUTES
→ DO NOT INVENT CHILDREN TO JUSTIFY DROPDOWN

DONOR CAROUSEL EXISTS
+
TARGET HAS VALID PEER ITEMS
→ CAROUSEL ROLE MAY TRANSFER

DONOR PRICING TOGGLE EXISTS
+
TARGET PRICING UNKNOWN
→ OMIT / DEFER
```

Therefore:

> **Interaction parity is conditional on target state existence.**

# 10. 3D truth rule

A donor 3D system may contribute:

```text
prominence
placement
camera grammar
interaction grammar
motion grammar
category-anchor role
material intensity
```

But target semantics must be sourced from:

```text
Soul
approved target taxonomy
known product/capability
known demonstration
approved target symbol system
```

If the exact target semantic object is unknown:

```text
PRESERVE ROLE
DEFER OBJECT DEFINITION
```

Do not create fictional products/features merely to give the object a label.

---

# 11. Proof truth rule

Donor proof architecture is reusable.

Donor proof content is not target proof.

For every proof slot:

```text
PROOF SOURCE?
STATUS?
PUBLIC-SAFE?
CLAIM CEILING?
```

Possible target proof dispositions:

```text
VERIFIED TARGET PROOF
DEMONSTRATION PROOF
PATTERN / EXAMPLE
REPLACE PROOF TYPE
OMIT
DEFER
```

Never:

```text
DONOR METRIC → TARGET METRIC
DONOR LOGO → TARGET LOGO
DONOR TESTIMONIAL → TARGET TESTIMONIAL
```

without target evidence.

---

# 12. Core / ecosystem ingestion rule

A target may sit inside a larger project or business ecosystem.

Core knowledge can be relevant, but must pass entity boundaries.

Record:

```text
SOURCE ENTITY
TARGET RELATIONSHIP
EVIDENCE STATUS
PUBLIC-SAFETY
CLAIM CEILING
```

Example:

```text
TECH capability
≠ automatically VertikALL product

Thradex history
≠ automatically VertikALL customer proof

Gallo / Turagua technical asset
≠ automatically VertikALL production case study
```

This prevents architecture from collapsing ecosystem layers into one public identity.


# 14. STEP 21 — Target Truth / Claim Test

v0.3 adds a dedicated post-build validation gate.

Check every public claim and content-bearing component against the Truth Baseline used by the blueprint.

Questions:

```text
Did any demonstration become a production claim?
Did any pattern become a proven product?
Did any proposed relationship become an existing program?
Did any donor metric survive as target proof?
Did any Core capability become a VertikALL claim without authority?
Did any unknown become polished copy?
```

Output:

```text
TARGET TRUTH / CLAIM EVIDENCE
```

A page can pass donor parity and Soul integrity and still fail this gate.

# 15. Updated validation stack

For R3:

```text
DONOR PARITY TEST
      ↓
SOUL INTEGRITY TEST
      ↓
TARGET TRUTH / CLAIM TEST
      ↓
MODE-AWARE VK TEST
```

The four tests answer different questions.

### Donor parity

Did we match the donor experience where promised?

### Soul integrity

Does the result belong to the target in meaning and identity?

### Target truth

Is every public fact/status/proof within the evidence ceiling?

### VK

Did the transformation satisfy the selected replication mode as a whole?
