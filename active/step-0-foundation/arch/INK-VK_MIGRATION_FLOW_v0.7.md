## 1. Why v0.7 exists

v0.6 already includes:

```text
Target Truth
Target Non-Regression
Content Capacity
Donor Job Decomposition
```

The Company pass exposed a new problem inside Truth:

```text
A TARGET CAN HAVE DEEP TRUE CONTENT
IN ONE INSTITUTIONAL DOMAIN
WHILE HAVING NO EVIDENCE
IN ANOTHER
```

Example:

```text
VertikALL mission / worldview / origin → strong
VertikALL team / partners / stats / careers / latest updates → not established
```

A generic `truth = yes` decision is too coarse for institutional pages.

v0.7 therefore strengthens Target Truth with a contextual **Institutional Evidence Scope** check.

Governing rule:

> **Evidence must match the domain, entity, and freshness of the claim it supports.**

# 5. Institutional evidence domains

Working domains:

```text
I0 — IDENTITY / NARRATIVE
I1 — ORGANIZATIONAL FACT
I2 — PEOPLE PROOF
I3 — RELATIONSHIP / EXTERNAL PROOF
I4 — QUANTITATIVE INSTITUTIONAL PROOF
I5 — ACTIVE INSTITUTIONAL STATE
```

These are not maturity levels.

They are evidence scopes.

A target may be very strong in I0 and empty in I2–I5.

---

# 6. Why this belongs inside Truth

The framework already asks:

```text
IS THIS CLAIM TRUE / SUPPORTED?
```

Company pages require the stronger question:

```text
TRUE AS WHAT?
TRUE FOR WHICH ENTITY?
TRUE AS OF WHEN?
```

Example:

```text
"VertikALL values long-term relationships"
```

may be true in I0.

It does not prove:

```text
formal partners
partner logos
partner counts
```

in I3/I4.

Therefore Evidence Scope is a dimensional refinement of Truth.

# 9. STEP 14 — institutional job admission

For institutional jobs ask:

```text
1. Does the target job exist?
2. Is there target truth?
3. Is it evidence of the correct domain?
4. Does it belong to the correct entity?
5. Is it current enough for the claim?
6. Is public use approved/safe?
7. Is capacity sufficient for the mechanism?
8. Can non-regression obligations be satisfied?
```

Only then:

```text
TRANSFER
REFRAME
OMIT
DEFER
```

# 10. Adjacent-domain anti-smuggling

```text
I0 RELATIONSHIP PHILOSOPHY

I0 ORIGIN STORY
≠ I4 COMPANY AGE / SCALE METRIC

I0 PEOPLE-CENTERED VALUES

≠ I5 ACTIVE CAREERS / LATEST NEWS
```

# 14. Proof-device semantic integrity

A donor proof device may be visually attractive but its semantic job matters.

Examples:

```text
bar chart
logo wall
team photography
map
count-up metric
news cards
```

If target evidence is missing:

```text
DO NOT KEEP THE DEVICE AND FILL IT WITH CONCEPTUAL CONTENT
IF THAT WOULD MAKE CONCEPTUAL CONTENT LOOK LIKE PROOF
```

A conceptual diagram is valid only as a conceptual diagram.

A generated image is valid only as conceptual/editorial imagery, not documentary people/company proof.

VTKALL Company is a new route.

Correct treatment:

```text
ROUTE-SPECIFIC LEGACY DEFECTS → NONE
GLOBAL TARGET DEFECTS          → INHERIT
```

Global constraints may still include:

```text

```

# 16. Route discovery vs institution invention

The Company case demonstrates a useful distinction.

A donor may help reveal that the target's existing content deserves a route not present in the current implementation.

Correct:

```text
TARGET HAS DEEP COMPANY STORY
+
DONOR HAS USEFUL COMPANY PAGE MODE
→ INTRODUCE COMPANY ROUTE
```

Incorrect:

```text
DONOR HAS PARTNERS / TEAM / CAREERS
→ INVENT TARGET PARTNERS / TEAM / CAREERS
```

Therefore:

> **Ink-VK may discover a missing target route; it may not invent a missing target institution.**
