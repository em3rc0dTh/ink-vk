# Ink-VK — Migration Flow v0.2

**Status:** PROPOSED / FOUNDATION ITERATION  
**Date:** 2026-08-14  
**Supersedes conceptually:** `Migration Flow v0.1` as the current working hypothesis; historical v0.1 remains preserved.

## 1. Why v0.2 exists

The VTKALL × Dayos case exposed a missing control in the earlier flow: Ink-VK cannot define transformation correctly until it knows the intended **replication mode**.

A project seeking pattern inspiration and a project seeking near-donor experiential parity require different contracts and different VK tests.

The new flow therefore separates:

```text
TARGET SOUL
DONOR FIDELITY
TARGET OWNERSHIP
PROVENANCE
```

instead of assuming donor distance should always increase.

# 3. STEP 00 — FRAME THE MIGRATION

Resolve:

```text

WHY CHANGE

EXPECTED OUTCOME
KNOWN RIGHTS / AUTHORIZATION CONTEXT
```

Output:

```text

sections
```

For an application/system:

```text

roles
```

Output:


# 5. STEP 02 — AUDIT TARGET

Determine how the current entity performs and where its expression fails or succeeds.

Output:

```text

```

```text
INFERENCE
```

# 15. STEP 12 — FREEZE FIDELITY / TRANSFORMATION CONTRACT

Now decide what happens to each layer.

Two axes are required.

## Axis A — Donor fidelity

```text
MATCH
MATCH BEHAVIOR / RE-AUTHOR EXPRESSION
TARGET-OWNED
NOT APPLICABLE
UNKNOWN
```

## Axis B — Target transformation action

```text
KEEP TARGET
ADAPT
REINTERPRET
REPLACE
REMOVE
INTRODUCE
MERGE
SPLIT
```

Output:

```text
FIDELITY / TRANSFORMATION CONTRACT
```

No blueprint should override this contract silently.


---

# 21. STEP 18 — SOUL INTEGRITY TEST

Check whether target meaning survived the donor shell.

Question:

> Does this still belong to the target in mission, business meaning, language, proof, relationship, and symbolic identity?

Output:

```text
SOUL INTEGRITY EVIDENCE
```

---

# 22. STEP 19 — MODE-AWARE VK TEST

VK changes by mode.

```text
R1 → donor independence
R2 → target-owned expression over donor structure
R3 → donor experiential parity + target Soul ownership
R4 → authorized reuse + target fit
```

The VK test must never fail a case merely because it achieved the donor similarity that its mode explicitly required.

Output:

```text
VK VALIDATION
```
