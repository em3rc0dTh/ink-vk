# Ink-VK — Migration Flow v1.0

**Status:** CANONICAL FOUNDATION BASELINE CANDIDATE  
**Date:** 2026-08-14  
**Supersedes operationally:** `INK-VK_MIGRATION_FLOW_v0.9.md`  
**Historical versions remain preserved.**

> **Chinese Method finds the DNA. Ink makes it belong. VK verifies the transformation.**

## 1. Purpose

This document freezes the first complete, repeatable Ink-VK campaign flow for applying Chinese Method to a new target entity.

Ink-VK is not limited to websites.

A target entity may be:

```text
website / digital experience
software product
application or module
workflow / operational system
architecture
repository / implementation
agent / prompt system
knowledge system
design system
service experience
```

The artifacts differ by domain; the control logic does not.

## 2. The four campaign bands

```text
RECON / TARGET CONTROL       00–07
MINING / DONOR INTELLIGENCE  08–12
INK / TRANSFORMATION         13–18
EXECUTION / VALIDATION       19–26
```

No band authorizes skipping the earlier source-of-truth work.

The framework is deliberately evidence-led:

```text
RECOVER BEFORE JUDGING
JUDGE BEFORE MINING
MINE BEFORE SELECTING
DISSECT BEFORE TRANSFORMING
CONTRACT BEFORE DESIGNING
DESIGN BEFORE PLANNING
PLAN BEFORE BUILDING
BUILD BEFORE CLAIMING PARITY
VALIDATE BEFORE PROMOTING LEARNINGS
```

## 4. STEP 00 — FRAME

### Question

What exactly are we transforming, why, and under which boundaries?

### Required inputs

```text
TARGET ENTITY
TARGET OWNER / AUTHORITY
TRANSFORMATION GOAL
CURRENT PAIN / OPPORTUNITY
IN-SCOPE SURFACES
OUT-OF-SCOPE SURFACES
CONSTRAINTS
EXPECTED OUTPUT TYPE
```

### Required output

`Migration Brief`

### Gate

Do not mine donors until the target and transformation objective are bounded.

## 5. STEP 01 — RECOVER TARGET

Recover what exists without redesigning it.

### Universal recovery dimensions

```text
structure
content / data
behavior
states
interfaces
roles
flows
dependencies
assets
runtime reality
ownership
```

### Domain adapters

For a website:

```text
routes
sections
navigation
copy
CTAs
forms
components
responsive states
motion
assets
```

For software:

```text
modules
features
entities
APIs
data
roles
integrations
runtime paths
```

For an operational system:

```text
actors
inputs
handoffs
records
authority
exceptions
outcomes
```

### Output

`Current Entity Recovery / AS-IS Map`

### Gate

Important unknowns must be explicit. Recovery does not need to solve them.

## 6. STEP 02 — AUDIT TARGET

Judge the recovered entity against its intended job.

Classify findings:

```text
STRENGTH
DEFECT
FRICTION
RISK
GAP
UNKNOWN
POSITIVE CONTROL
```

Output:

`Target Audit`

## 7. STEP 03 — FREEZE TARGET NON-REGRESSION

Convert known defects and positive controls into obligations.

```text
MUST NOT RETURN
MUST PRESERVE
MUST VERIFY
```

This prevents donor fidelity from reintroducing target failures.

Output:

`Target Non-Regression Baseline`

## 8. STEP 04 — EXTRACT TARGET SOUL

Soul is the target-owned meaning that the migration is not allowed to erase.

At minimum evaluate:

```text
mission
worldview
audience
business reality
operational reality
voice
relationship model
trust model
proof discipline
symbolic language
emotional promise
constraints
identity
```

Soul is not equivalent to colors, typography, or logo.

Output:

`Target Soul Contract`

## 9. STEP 05 — FREEZE TARGET TRUTH

Determine what the target is actually allowed to claim, show, activate, or imply.

Truth dimensions may include:

```text
facts
capabilities
content inventory
evidence scope
status
public-safety
freshness
functional dependency level
rights / ownership
```

Use existing gates when applicable:

- Target Truth Gate;
- Content Capacity Gate;
- Institutional Evidence Scope Gate;
- Interaction Dependency Truth Gate.

Output:

`Target Truth Baseline`

## 10. STEP 06 — SELECT REPLICATION MODE

Every case declares intended donor fidelity.

```text
R1 — Pattern Transfer
R2 — Structural Transposition
R3 — Experiential Soul Transposition
R4 — Authorized Implementation Reuse overlay
```

Replication mode may vary by layer.

Example:

```text
STRUCTURE      R3
INTERACTION    R3
MOTION         R2/R3
COPY           TARGET-OWNED
BRAND          TARGET-OWNED
CODE           NO R4
ASSETS         NO R4
```

Output:

`Replication Mode Contract`

## 11. STEP 07 — DEFINE TRANSFORMATION NEED

Convert target recovery + audit + soul + truth into a donor search brief.

Do not search for “a cool site” or “something similar.”

Search for missing intelligence.

Output:

`Transformation Target / Mining Brief`

## 12. STEP 08 — MINE

Search legitimate public or authorized sources:

```text
web experiences
open-source repositories
products
design systems
interaction patterns
architectures
prompts / agent patterns
operational models
technical papers / documentation
```

Every source remains evidence until selected.

Output:

`Mining Site`

## 13. STEP 09 — BUILD QUARRIES / SCREEN DONORS

Each concrete source becomes a quarry with provenance.

Classify candidates:

```text
PRIMARY DONOR
SECONDARY DONOR
PATTERN SOURCE
REFERENCE ONLY
REJECT
```

Screen by:

```text
relevance
quality
structural fit
behavioral fit
content compatibility
technical feasibility
adaptability
provenance / rights
risk
```

A rich source is not automatically the correct donor.

Output:

`Quarry Set + Donor Shortlist`

## 14. STEP 10 — RECOVER DONOR

Recover the selected donor before critique.

```text
route/module topology
information architecture
components
states
interactions
responsive transformations
motion
assets
data / contracts
runtime behavior
```

Output:

`Donor Recovery Map`

## 15. STEP 11 — DISSECT DONOR

Ask why the donor works.

Decompose donor pages/modules into jobs rather than treating each page as an indivisible template.

Candidate jobs:

```text
orientation
identity
decision
comparison
proof
process
trust
navigation / disclosure
conversion
status
continuity
exception handling
```

Output:

`Donor Dissection + Job Ledger`

## 16. STEP 12 — EXTRACT DNA + FIDELITY CONTRACT

DNA is reusable intelligence, not literal donor expression.

Each DNA record should contain:

```text
ID
PATTERN
OBSERVED EVIDENCE
INFERRED PRINCIPLE
JOB
TRANSFER CONDITIONS
NON-TRANSFERABLE EXPRESSION
RISKS
CONFIDENCE
```

Then define fidelity dimension by dimension:

```text
MATCH
MATCH BEHAVIOR / RE-AUTHOR EXPRESSION
TARGET-OWNED
NOT APPLICABLE
UNKNOWN
```

Output:

`Donor DNA Catalogue + Fidelity Contract`

## 17. STEP 13 — MAP TARGET × DONOR × SOUL

Compare:

```text
TARGET CURRENT STATE
TARGET DEFECT / OPPORTUNITY
TARGET SOUL
TARGET TRUTH / CAPACITY
DONOR DNA / JOB
REPLICATION MODE
```

Output dispositions:

```text
KEEP
ADAPT
REPLACE
REMOVE
INTRODUCE
REINTERPRET
MERGE
SPLIT
DEFER
```

`INVENT` is not a valid way to fill an unsupported target slot.

Output:

`Target × Donor × Soul Matrix`

## 18. STEP 14 — TARGET-TRUTH / CAPACITY / DEPENDENCY GATE

Before transformation is frozen, test whether every proposed target element has enough truth behind it.

Questions:

```text
Is the content real?
Is there enough variation to justify the UI/system mechanism?
Does the evidence belong to the correct entity/domain?
Is it current enough?
Does the target have the dependencies required by the affordance?
```

Possible disposition:

```text
ADMIT
REDUCE
REFRAME
OMIT
DEFER
UNKNOWN
```

## 19. STEP 15 — TARGET NON-REGRESSION GATE

Every proposed transformation is tested against Step 03.

Donor fidelity does not excuse known target regression.

## 20. STEP 16 — TRANSFORMATION CONTRACT

Freeze, unit by unit, what intelligence survives and what must not be copied.

Required record:

```text
TARGET UNIT
DONOR JOB / DNA
DECISION
TARGET-SIDE INTERPRETATION
TRUTH AUTHORITY
SOUL AUTHORITY
FIDELITY LEVEL
WHAT MUST NOT BE COPIED
DEPENDENCIES
RISKS
VALIDATION REQUIRED
```

Output:

`Transformation Contract`

## 21. STEP 17 — APPLY INK

Ink transforms donor intelligence until the design/system is target-owned in meaning.

The test is:

> If the donor disappeared tomorrow, could every important target decision still be justified from target Soul, truth, user/job needs, and the approved fidelity contract?

Ink may change:

```text
terminology
brand
visual semantics
content
proof
workflow
interaction meaning
architecture
data ownership
states
symbols
motion semantics
trust mechanisms
```

Output:

`Ink Specification`

## 22. STEP 18 — DESIGN TARGET BLUEPRINT + COHERENCE

Design the target system, not isolated screens/modules.

Resolve as applicable:

```text
global shell / system frame
route/module families
information architecture
surface/state semantics
typographic/information roles
spatial rules
density allocation
visual-device allocation
motion hierarchy
proof/status grammar
component families
responsive/adaptive continuity
interaction-state boundaries
closure / terminal states
```

For multi-route/module targets, run Cross-Route/Cross-Entity Coherence.

### Design Freeze rule

Remaining unknowns are classified:

```text
FROZEN
BOUNDED / IMPLEMENTATION-SAFE
DEFERRED / OPTIONAL DEPENDENCY
BLOCKING UNKNOWN
```

PLAN requires:

```text
BLOCKING UNKNOWN = 0
```

Output:

`Consolidated Target Blueprint + Design Freeze`

## 23. STEP 19 — PLAN MIGRATION

Convert the blueprint into small, testable slices.

Each slice must state:

```text
scope
source authority
target contract
dependencies
implementation boundary
acceptance evidence
rollback / failure condition where relevant
```

No slice may redesign the product silently.

Output:

`Controlled Migration Plan`

## 24. STEP 20 — BUILD / MIGRATE

Implementation authority is:

```text
TARGET TRUTH
+
TRANSFORMATION CONTRACT
+
INK SPECIFICATION
+
FROZEN BLUEPRINT
+
PLAN
```

The donor is no longer direct implementation authority unless R4 explicitly authorizes reuse.

## 25. STEP 21 — DONOR PARITY TEST

Validate only the fidelity dimensions required by the selected replication mode.

This is not a pixel-copy test unless the contract explicitly requires that level and reuse is legitimate.

## 26. STEP 22 — SOUL INTEGRITY TEST

Verify that target identity and meaning survived implementation.

Questions:

```text
Does the result speak as the target?
Does it use target proof and constraints?
Do interactions mean the right thing for this target?
Would a stakeholder recognize their operating reality?
```

## 27. STEP 23 — TARGET TRUTH / CLAIM / DEPENDENCY TEST

Verify that implementation does not upgrade:

```text
status
proof
content depth
institutional maturity
functional capability
downstream outcomes
rights / ownership
```

beyond the frozen target truth.

## 28. STEP 24 — TARGET NON-REGRESSION TEST

Verify every Step 03 obligation across all relevant states, viewports, flows, and modules.

## 29. STEP 25 — MODE-AWARE VK TEST

VK asks whether the transformation achieved the declared replication mode.

### R1

Target justification dominates and donor recognizability is incidental.

### R2

Structural similarity is intentional; target expression and meaning dominate.

### R3

Donor experiential fidelity is expected where contracted, while target Soul, truth, identity, and semantics remain authoritative.

### R4

Direct reuse must pass authorization, provenance, license, compatibility, and attribution requirements.

Possible result:

```text
PASS
FAIL — DONOR FIDELITY
FAIL — SOUL
FAIL — TRUTH
FAIL — NON-REGRESSION
FAIL — PROVENANCE
LOCAL PASS / GLOBAL FAIL
NOT TESTED
```

## 30. STEP 26 — EVIDENCE, MEMORY & FRAMEWORK LEARNING

Close the campaign with an evidence ledger:

```text
what changed
why
source / quarry lineage
DNA selected
DNA rejected
transformation decisions
Soul decisions
truth decisions
implementation evidence
validation results
known unknowns
future capabilities
```

Promote reusable learnings only with explicit status:

```text
CASE-SPECIFIC
VALIDATED BY ONE CASE
CROSS-CASE CANDIDATE
READY FOR FOUNDATION REVIEW
ADOPTED FOUNDATION RULE
```

A single successful case does not prove universal validity.

## 31. Gate discipline

A completed gate is not reopened merely because a later phase is difficult.

Reopen only when:

```text
new evidence contradicts the baseline
an authority changed
a dependency changed
a claim was invalidated
a design-shaping unknown was misclassified
```

Every reopening requires:

```text
JUSTIFICATION
AFFECTED ARTIFACTS
DELTA
NEW GATE RESULT
```

## 32. Evidence discipline

Use:

```text
OBSERVED
INFERRED
UNKNOWN
```

Do not silently convert one into another.

Where useful, preserve evidence hierarchy:

```text
Q0 — raw capture / direct artifact
Q1 — live source / runtime
Q2 — extracted system
Q3 — recovered topology
Q4 — interpretation
```

Higher interpretation does not erase lower evidence.

## 33. Rights / provenance discipline

Public reachability does not imply reuse permission.

Separate:

```text
STUDY
PATTERN EXTRACTION
REIMPLEMENTATION
DIRECT CODE REUSE
DIRECT ASSET REUSE
COPY REUSE
```

R4 is required for direct implementation reuse and must be supported by rights/provenance evidence.

## 34. Canonical completion test

A campaign is complete when a future engineer or agent can answer:

```text
What was the target before?
What could not regress?
What is the target Soul?
What target truth was frozen?
What donor fidelity was intended?
What did we mine and why?
What donor DNA was extracted?
What was transferred, rejected, or deferred?
Why does the transformed result belong to the target?
What was built?
What evidence proves it?
What did VK conclude?
What did Ink-VK learn for the next case?
```

## 35. Governing statement

> **Ink-VK is a controlled source-to-soul transformation system. Chinese Method discovers and dissects useful existing intelligence; Ink re-authors that intelligence around target Soul and truth; VK verifies that the declared fidelity was achieved without losing target ownership, truth, provenance, or non-regression.**
