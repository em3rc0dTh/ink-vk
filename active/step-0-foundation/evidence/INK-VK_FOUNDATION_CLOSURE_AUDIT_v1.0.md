## 3. Gaps discovered and closed through VTKALL × Dayos

The initial concept was too small. The canonical case exposed additional controls required for a serious reusable framework.

### 3.1 Replication fidelity ambiguity — CLOSED

Problem:

Ink-VK originally implied that donor resemblance should always be reduced.

Closure:

```text
R1 Pattern Transfer
R2 Structural Transposition
R3 Experiential Soul Transposition
R4 Authorized Implementation Reuse overlay
```

### 3.2 Target truth — CLOSED

Problem:

A donor can contain richer commercial, institutional, content, or interactive states than the target can honestly support.

Closure:

- Target Truth Gate;
- claim ceilings;
- FILL / REFRAME / OMIT / DEFER discipline;
- `INVENT` is not accepted as a target-truth action.

### 3.3 Target non-regression — CLOSED

Problem:

Donor fidelity could silently recreate defects already discovered in the target.

Closure:

Target Non-Regression Baseline and post-build validation.

### 3.4 Content capacity — CLOSED

Problem:

A donor library pattern may require more real records or variation than the target has.

Closure:

C0–C4 capacity model and rule:

> **Design for future capacity; render current truth.**

### 3.5 Donor page over-transfer — CLOSED

Problem:

A donor page may mix pricing, proof, process, FAQ, conversion, navigation, and other jobs.

Closure:

Donor Job Decomposition Gate.

### 3.6 Institutional proof leakage — CLOSED

Problem:

Strong narrative does not prove team, partner, quantitative, or active institutional depth.

Closure:

Institutional Evidence Scope Gate.

### 3.7 Interaction promise leakage — CLOSED

Problem:

A visible donor control could imply downstream capability the target does not possess.

Closure:

D0–D5 Interaction Dependency Truth model.

### 3.8 Local route success / global system failure — CLOSED

Problem:

Every page can look valid individually while the target feels incoherent or over-templated globally.

Closure:

Cross-Route Coherence Gate + signature-device allocation.

### 3.9 Unknown handling — CLOSED

Problem:

`UNKNOWN = 0` creates false precision; leaving everything open creates hidden design work in BUILD.

Closure:

```text
FROZEN
BOUNDED / IMPLEMENTATION-SAFE
DEFERRED / OPTIONAL DEPENDENCY
BLOCKING UNKNOWN
```

PLAN requires `BLOCKING UNKNOWN = 0`.

### 3.10 Concept-frame authority ambiguity — CLOSED

Problem:

A rendered screenshot can accidentally be treated as stronger implementation authority than a previously frozen semantic blueprint.

Closure from the current VTKALL visual target review:

> **Concept frames are evidence of composition; they do not silently override stronger frozen semantic contracts.**
