## 3. Supported five-step sequence

The current target source explicitly defines:

```text
01 — UNDERSTAND THE BUSINESS FLOW
Begin with how the business actually works today:
customers, requests, appointments, services, staff, and handoffs.

02 — MAP RECURRING FRICTION
Identify where follow-up is missed,
information gets repeated,
appointments become unclear,
or work loses visibility.

03 — CONFIGURE THE OPERATING FLOW
Shape the practical flow around the business:
service intake, customer records, scheduling, status, and owner visibility.

04 — ACTIVATE FOLLOW-UP AND CONTROL
Reduce repeated manual contact and give the team clearer ways
to confirm, update, track, and respond.

05 — IMPROVE WITH REAL USAGE
Use what happens in daily work to adjust the flow,
simplify the process,
and make control easier over time.
```

Evidence class:

```text
T0 — DIRECT TARGET FACT / CURRENT APPROVED CONTENT
```

The order is explicit and therefore legitimately sequential.

## 8. Existing Method visual-audit baseline

Recovered target defects:

### M01 — whitespace imbalance + clipping

- large unused upper-right area;
- supporting content cut at viewport bottom.

### M02 — unresolved next-section visibility

- large empty right-side region;
- following `FIVE STEPS` state visible before current state feels resolved.

### M03 — long list clipping

- five-step vertical list extends beyond viewport;
- step 03 begins while the list is visibly cut.

### M04 — continuation without a new state

- steps 02–05 require a second viewport;
- proves the current list is a long continuous component, not multiple deliberate sections.

### M05 — dark section + CTA mixing

- `NO TECHNICAL BURDEN` and next white CTA appear together;
- next headline itself is clipped.

### M06 — previous state + CTA + footer collapse

- three visual states compete in one captured view.

Non-regression summary:

```text
NO meaningless lateral void while content clips
NO accidental next-section leakage
NO vertically stacked five-step list that becomes an unresolved clipped wall
NO CTA/footer collapse
NO forced single-viewport containment for a process that legitimately needs space
```
