**QUESTION**  
Which target-owned color/surface roles are frozen strongly enough to PLAN the system without reproducing Dayos identity or letting BUILD choose a new visual language?

**WHY IT AFFECTS IMPLEMENTATION**  
Surface primitives, states, CTAs, status grammar and component composition depend on a stable role map.

**CURRENT AUTHORITY**  
Blueprint S0–S5 surface roles + Soul Contract current visual expression + target `globals.css`.

**TARGET EVIDENCE**

```text
#faf8f2  warm canvas
#ffffff  light surface
#211f1b  ink
#66737e  muted
#d9d4c8  line
#f5c556  amber
#e97924  orange action
#2f5f7c  trust / structure blue
#4f7a58  growth / progression green
#161616  dark band
```

**DONOR EVIDENCE**  
Dayos demonstrates semantic surface-state contrast and strong accent assignment, but donor colors are not target assets.

**KNOWN**

- semantic surface classes S0–S5 already exist;
- current target palette is real target evidence;
- strong accents require a semantic job;
- Dayos palette must not be copied as identity.

**UNKNOWN**

- exact final radii;
- exact shadow recipes;
- whether every current target token survives numerically unchanged after implementation calibration.

**DECISION TYPE**  
`target design decision + target evidence recovery`

**NON-REGRESSION RISK**  
Decorative multi-color use may increase visual noise or hide section boundaries.

**SOUL RISK**  
Importing donor colors would make the result donor-coded rather than VertikALL-owned.

**R3 FIDELITY RISK**  
Keeping only current card styling instead of donor-like surface-state choreography would under-transfer the experiential system.

**DECISION / DEFER**  
Freeze the current target palette as the v0.1 token source and freeze its semantic role mapping. Exact radii, shadows and optical adjustments remain bounded implementation calibration, not permission to create a new palette.

**PLAN BLOCKING?**  
`NO after contract closure`

## DF-04 — Home 3D semantic art direction

**QUESTION**  
What does Home 3D mean in VertikALL terms?

**WHY IT AFFECTS IMPLEMENTATION**  
The meaning determines object states, asset production, scene architecture and narrative choreography.

**CURRENT AUTHORITY**  
Home is the primary 3D owner. Soul vocabulary includes network, node, flow, handoff, signal, path, visibility, control, leverage and connection.

**TARGET EVIDENCE**  
`Everything is a network` is a Soul invariant. Organize / Follow Up / Control is an approved source-derived taxonomy, not product SKUs.

**DONOR EVIDENCE**  
Dayos uses 3D as semantic identity and compositional counterweight, not merely ornament.

**KNOWN**  
The 3D must carry meaning and remain conceptually separate from product/evidence UI.

**UNKNOWN**  
Exact geometry, material, lighting, camera and rendering technology.

**DECISION TYPE**  
`target design decision`

**DECISION / DEFER**  
Freeze an **Operational Network / Flow Graph** semantic system for Home. One primary connected object may move through three readable conceptual states:

```text
ORGANIZE   → scattered nodes become structured / grouped
FOLLOW UP  → pending paths/signals reconnect and continue
CONTROL    → system relationships become visible / legible as a whole
```

Exact art-production parameters remain bounded by this semantic story.

**PLAN BLOCKING?**  
`NO after 3D contract`

**UNKNOWN**  
Final rendering implementation and whether an independently licensed third-party base asset is eventually useful.

**DECISION TYPE**  
`provenance decision`

**DECISION / DEFER**  
Freeze original target-owned production as the default path. Allowed sources are:

Forbidden:

```text

reverse-extracted donor assets
untracked generated/downloaded assets
```

**PLAN BLOCKING?**  
`NO after production boundary`

## DF-07 — Responsive breakpoint / transformation specification

**QUESTION**  
Which responsive transformations and numeric anchors can PLAN assume?

**WHY IT AFFECTS IMPLEMENTATION**  
Responsive architecture decides composition ordering, navigation mode, process orientation and 3D dominance.

**TARGET EVIDENCE**

```text

760px

```

The legacy visual audit proves the existing composition around those values still has clipping/crowding defects, so the values are evidence, not perfection.

**DONOR EVIDENCE**  
Exact donor breakpoints are not recovered from the static capture set.

**KNOWN**

- job/order must survive;
- desktop column count is not sacred;
- Method becomes vertical on narrow screens;
- Company local orientation must compact;
- Start becomes a bounded full-width focused surface;
- no clipping or cramped peer cards.

**DECISION TYPE**  
`target evidence + target design decision`

**DECISION / DEFER**  
Freeze the existing target anchors as v0.1 responsive **baseline tokens**, with new transformation ownership:

```text
≤ 920px  major field/column transformation
≤ 760px  navigation + local-orientation mobile mode
≤ 620px  compact handset density / single-sequence mode
```

Numerical movement is calibration-safe only when required to satisfy no-clipping/readability tests; PLAN may not change which semantic transformation belongs to each layer.

**PLAN BLOCKING?**  
`NO after responsive contract`
