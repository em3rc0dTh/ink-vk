# VTKALL × Dayos — Fidelity Contract v0.1

**Project:** Ink-VK  
**Target:** VertikALL website  
**Donor:** Dayos  
**Replication mode:** `R3 — EXPERIENTIAL SOUL TRANSPOSITION`  
**Status:** PROPOSED / REQUIRED BEFORE PAGE MAPPING  
**Date:** 2026-08-14

## 1. Authoritative clarification

This case intentionally seeks **high donor fidelity**.

The transformation goal is not merely:

> learn from Dayos and produce a different-looking VTKALL site.

The goal is closer to:

> reproduce the Dayos experiential system with VertikALL Soul.

Therefore donor resemblance is expected and desired across the layers explicitly approved below.

The important transformation is not reducing structural similarity. It is replacing donor identity and meaning with target identity and meaning.

## 3. What “same spirit” means in this case

`Same spirit` is too vague to function as an implementation contract unless decomposed.

For this migration it means preserving, where evidence supports it:

```text
editorial confidence
clear section state changes
intentional visual pacing
large-scale compositional moves
compact global framing
controlled disclosure
purpose-driven density
strong typography as spatial mass
claim → mechanism → proof rhythm
semantic visual devices
explicit route closure
tactile / dimensional 3D presence
high-confidence interaction behavior
```

It does **not** mean adopting Dayos's business personality, copy, claims, product semantics, or visual branding as VertikALL identity.

## 4. Fidelity dimensions

### 4.1 Route / page-family structure

**Decision:** MATCH / MAP WITH PURPOSE

The target should preserve the donor's page-family intelligence where a VTKALL route can be mapped to the same information job.

Required next work:

```text
VTKALL ROUTE
↔
DAYOS ROUTE / PAGE MODE
↔
WHY THE JOB MATCHES
```

No route should be mapped only because the donor page looks attractive.

---

### 4.2 Section topology

**Decision:** HIGH FIDELITY

Where a target route is paired with a donor route, preserve the donor's section choreography as closely as the VTKALL content allows.

This includes:

```text
opening state
narrative progression
surface handoffs
proof placement
visual interruption
CTA timing
closure
footer transition
```

Target content may require semantic adjustment, but arbitrary restructuring should not occur without an explicit reason.

---

### 4.3 Navigation behavior

**Decision:** HIGH FIDELITY

Preserve the donor's interaction grammar for:

```text
global navigation
compact disclosure
menu expansion / collapse
local orientation where justified
primary action persistence
```

Labels, route names, brand mark, and destination semantics remain VTKALL-owned.

---

### 4.4 Interaction behavior

**Decision:** HIGH FIDELITY

The target should seek parity in the behavior of comparable interactive elements:

```text
hover response
focus / active states
menu transitions
scroll-linked changes
section entrances
state disclosure
card response
CTA behavior
```

Exact behavior must later be recovered from donor evidence rather than guessed.

---

### 4.5 Motion and pacing

**Decision:** HIGH FIDELITY / EVIDENCE REQUIRED

Preserve the donor's perceived rhythm:

```text
entrance timing
transition pacing
scroll cadence
layer movement
3D motion relationship
pause / reveal behavior
```

Do not invent exact timings before donor motion evidence has been measured or observed sufficiently.

---

### 4.6 3D graphic system

**Decision:** HIGH-FIDELITY SYSTEM / TARGET-OWNED SEMANTICS

VertikALL should intentionally preserve the donor-like use of 3D as a major part of the composition rather than reducing it to decorative background art.

Preserve as closely as evidence supports:

```text
prominence
placement
scale relationship
camera / perspective logic
depth behavior
motion grammar
interaction response
material / tactile intensity
role within the section
```

Re-author through VertikALL Soul:

```text
object meaning
labels
brand marks
color semantics
business symbolism
content relationship
```

Candidate VTKALL semantics come from:

```text
network
node
flow
connection
visibility
control
leverage
operational module
signal
path
```

### Direct reuse boundary

`same 3D graphics` in experiential terms does not automatically mean reuse of Dayos source 3D files.

Direct reuse of proprietary 3D assets, source models, textures, or code requires separate authorization / rights evidence.

---

### 4.7 Spatial composition

**Decision:** HIGH FIDELITY

Preserve the donor's compositional grammar where mapped:

```text
wide field + controlled reading width
large typographic mass
secondary visual payload
intentional empty field
purpose-driven density
surface framing
visual balance
```

This dimension directly addresses the current VTKALL visual-recovery issues of cramped central content, clipping, and unused lateral space.

---

### 4.8 Surface language

**Decision:** MATCH BEHAVIOR / RE-AUTHOR BRAND EXPRESSION

Preserve the functional use of:

```text
contrast
surface-state change
section differentiation
visual closure
```

The exact Dayos palette does not become VTKALL by default.

VertikALL colors, materials, and identity must be deliberately re-systematized inside the same experiential role.

---

### 4.9 Typography

**Decision:** MATCH ROLE / RE-AUTHOR IDENTITY

Preserve the donor principle that typography participates in geometry and hierarchy.

Do not assume the exact donor font files, font family, or word shapes are target assets.

The target typography must reproduce equivalent authority, scale, density, and compositional function while remaining valid for VTKALL.

---

### 4.10 Proof grammar

**Decision:** MATCH STRUCTURE / TARGET-OWNED EVIDENCE

Preserve:

```text
CLAIM
  ↓
MECHANISM / EXAMPLE
  ↓
PROOF
```

Replace all donor evidence with valid VTKALL evidence.

No Dayos metrics, product claims, screenshots, partners, or testimonials may become VertikALL evidence merely to preserve visual parity.

---

### 4.11 Responsive transformation

**Decision:** HIGH FIDELITY

The desktop composition alone is not the donor system.

Recover and preserve, as evidence permits:

```text
what disappears
what reorders
what collapses
what becomes horizontal / vertical
what is reduced
what remains dominant
how 3D behaves
how navigation changes
how section rhythm changes
```

Responsive behavior is part of experiential fidelity, not a later cleanup task.

## 8. Acceptance model

The final site must pass separate gates.

### A — Donor Experience Parity

```text
route / page-mode parity
section-topology parity
interaction parity
navigation parity
motion / pacing parity
3D-system parity
responsive parity
closure / CTA rhythm parity
```

### B — VertikALL Soul Integrity

```text
mission preserved
audience preserved
voice preserved
business meaning preserved
proof honesty preserved
ally / harbor behavior preserved
network / leverage worldview represented appropriately
```

### C — Ownership / Provenance

```text
no donor claim masquerades as target claim
no donor evidence masquerades as target evidence
direct asset / code reuse has known authority
unknown rights remain explicit
```

A build is not valid merely because it looks close to Dayos.

A build is not valid merely because it contains VertikALL colors and copy.

The intended result requires **both** donor experiential fidelity and target Soul fidelity.
