**Project:** Ink-VK  
**Target:** VertikALL website  
**Donor:** Dayos  
**Replication mode:** `R3 — EXPERIENTIAL SOUL TRANSPOSITION`  
**Status:** PROPOSED / ROUTE-LEVEL MAPPING  
**Date:** 2026-08-14

## 1. Purpose

This document is the first concrete bridge between:

```text
DAYOS EXPERIENCE SYSTEM
and
VERTIKALL SOUL
```

The goal is **not** to force the existing five-route VTKALL website into its current information architecture.

The authoritative case direction is higher fidelity:

> the new VertikALL website should reproduce the Dayos experiential structure as closely as practical while replacing Dayos identity and business meaning with VertikALL Soul.

Therefore the current VTKALL route set is treated as **content evidence**, not automatically as the final route topology.

```text

+
borrow Dayos styling
```


This is a structural migration, not a reskin.

# 10. PLANS → METHOD

## Donor job

Dayos Plans combines a decision surface with a connected process sequence.

## VTKALL job

The current VTKALL Method already has a five-step operating sequence:

```text
UNDERSTAND THE FLOW
MAP FRICTION
CONFIGURE THE FLOW
ACTIVATE FOLLOW-UP / CONTROL
IMPROVE WITH REAL USAGE
```

This is a strong semantic match for the donor's process geometry.

## Decision

Preserve the **decision + process page mode** but replace any commercial/pricing assumption with a VertikALL-native starting decision.

Candidate opening decision job:

```text
What part of your operation needs organizing first?
```

Then express the method as a connected spatial sequence rather than a generic stacked list.

This also validates the earlier VTKALL visual-review suggestion that sequential content should be represented spatially.

# 13. SCHEDULE DEMO → START

This is the cleanest direct mapping.

```text
Tell us what business flow you want to organize.
```

# 14. 3D semantic mapping by route family

The donor 3D system should remain high-fidelity in role, but its meaning should be re-authored.

## Home

Candidate semantics:

```text
hidden operational network becoming visible
```

## Capabilities

```text
ORGANIZE   → connected structure / ordered nodes
FOLLOW UP  → signal / handoff / moving state
CONTROL    → visibility / feedback / operational field
```

## Solutions

3D can identify solution families without changing the shared shell.

## Method

3D may reinforce progression / transformation rather than represent an arbitrary object.

## Partnership

3D may express connection, leverage, or collaborative growth.

## Company

Use 3D only if it reinforces mission/worldview; photography or other proof may be semantically stronger for company reality.

**Status:** SEMANTIC DIRECTION ONLY. Final 3D models are not approved here.
