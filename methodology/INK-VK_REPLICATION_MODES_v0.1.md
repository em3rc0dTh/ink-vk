# Ink-VK — Replication Modes v0.1

**Status:** PROPOSED / FOUNDATION CANDIDATE  
**Project:** Ink-VK  
**Date:** 2026-08-14

## 1. Why this document exists

Early Ink-VK work treated donor resemblance as something that should always be reduced through transformation. The VTKALL × Dayos case exposed that this is not universally correct.

Some migrations intentionally want only donor intelligence. Others intentionally want the donor's structure, interactions, spatial behavior, motion grammar, and experiential character reproduced with high fidelity while replacing the donor's identity with the target's Soul.

Ink-VK therefore needs an explicit **Replication Mode** before it can define the correct transformation contract or VK test.

The framework must never assume that every case has the same desired distance from the donor.

---

## 2. Core distinction

```text
DONOR INTELLIGENCE
≠
DONOR EXPERIENCE
≠
DONOR IDENTITY
≠
DONOR ASSETS / CODE
```

A project may intentionally preserve one layer while replacing another.

The question is not simply:

> How much are we copying?

The stronger question is:

> Which donor layers are authoritative for this migration, and which layers must remain target-owned?

---

## 3. Replication modes

### R1 — PATTERN TRANSFER

**Intent:** extract reusable principles and re-express them freely.

Typical donor authority:

```text
information principles
interaction principles
density logic
hierarchy
proof grammar
navigation ideas
```

Expected target result:

- may look substantially different from the donor;
- donor resemblance is not a goal;
- target expression is dominant.

VK emphasis:

> Can the final decisions be justified from the target without dependence on donor appearance?

---

### R2 — STRUCTURAL TRANSPOSITION

**Intent:** preserve substantial information architecture, page-family logic, section topology, or interaction organization while re-authoring the visual expression.

Typical donor authority:

```text
route structure
page families
section sequence
interaction topology
content density model
responsive transformation logic
```

Expected target result:

- structural similarity is intentional;
- visual identity may differ significantly;
- target content and brand remain authoritative.

VK emphasis:

> Does the target inherit useful donor structure without inheriting donor-specific identity or assumptions?

---

### R3 — EXPERIENTIAL SOUL TRANSPOSITION

**Intent:** reproduce the donor's experiential system with high fidelity while replacing donor identity, meaning, and client-specific substance with the target's Soul.

Typical donor authority may include:

```text
route/page structure
section architecture
interaction grammar
navigation behavior
motion and scroll pacing
surface handoffs
composition rhythm
responsive behavior
3D visual-system role
spatial hierarchy
visual density
page closure behavior
```

Target authority remains:

```text
brand
mission
business meaning
copy
service/product taxonomy
proof
claims
audience
voice
symbols
client-specific visual semantics
```

Expected target result:

- the donor relationship may be visually and behaviorally recognizable;
- that resemblance is not automatically a failure;
- the result must still be unmistakably owned by the target in identity and meaning.

VK emphasis:

> Did we preserve the intended donor experience while successfully replacing the donor's identity with the target's Soul?

This mode requires **two validations**, not one:

```text
DONOR PARITY TEST
+
SOUL INTEGRITY TEST
```

---

### R4 — AUTHORIZED IMPLEMENTATION REUSE

**Intent:** reuse donor code, assets, components, models, design files, or other implementation material directly when authorization, license, provenance, and compatibility support that reuse.

This mode may coexist with R1, R2, or R3.

It is not inferred from visual similarity.

Required evidence includes, as applicable:

```text
license
authorization
source provenance
asset rights
attribution requirements
compatibility constraints
```

Unknown rights remain UNKNOWN.

VK emphasis:

> Is direct reuse both authorized and correctly transformed for the target context?

---

## 4. Replication mode is a contract input

Every Ink-VK case must state its intended mode before the final donor transformation contract is frozen.

Required field:

```text
REPLICATION MODE
R1 | R2 | R3 | R4-overlay
```

A case may use different modes for different layers.

Example:

```text
STRUCTURE            R3
INTERACTION          R3
MOTION               R3
3D SYSTEM            R3
COPY                  TARGET-OWNED
BRAND                 TARGET-OWNED
PROPRIETARY ASSETS    NO DIRECT REUSE
CODE                  R4 only if authorization exists
```

## 5. Fidelity dimensions

For high-fidelity cases, Ink-VK must define fidelity dimension by dimension instead of using vague words such as "same" or "inspired by".

Candidate dimensions:

```text
ROUTE TOPOLOGY
SECTION ORDER
PAGE FAMILY
NAVIGATION
INTERACTION
MOTION
SCROLL PACING
SURFACE HANDOFFS
DENSITY
TYPOGRAPHIC ROLE
SPATIAL COMPOSITION
3D ROLE
3D CAMERA / DEPTH GRAMMAR
RESPONSIVE TRANSFORMATION
CTA / CLOSURE RHYTHM
```

Each dimension should be classified as:

```text
MATCH
MATCH BEHAVIOR / RE-AUTHOR EXPRESSION
TARGET-OWNED
NOT APPLICABLE
UNKNOWN
```

## 6. Soul is not a cosmetic layer

In R3, Soul cannot mean only:

```text
logo
colors
fonts
copy replacement
```

Soul must include the target's:

```text
mission
worldview
audience
relationship model
business reality
language
trust model
proof discipline
symbolic vocabulary
emotional promise
constraints
operational truth
```

If those do not change the meaning of the replicated experience, the result is only a rebrand.

---

## 7. 3D and visual-system rule

R3 may intentionally reproduce a donor's 3D prominence, placement, motion grammar, spatial role, tactile quality, and composition behavior.

This does **not** automatically authorize direct reuse of donor source assets.

The framework therefore separates:

```text
3D SYSTEM FIDELITY
from
3D ASSET REUSE
```

A target can preserve the same 3D experiential role while re-authoring models, materials, labels, symbols, colors, or semantic meaning around the target Soul.

Direct donor asset reuse belongs under R4 and requires evidence.

---

## 8. Mode-aware VK test

### For R1

Donor recognizability should be low and target justification should dominate.

### For R2

Structural similarity is acceptable; target expression and meaning must dominate.

### For R3

Donor experiential similarity is expected.

A passing result requires:

```text
DONOR SYSTEM FIDELITY     PASS
TARGET SOUL INTEGRITY     PASS
TARGET CONTENT OWNERSHIP  PASS
PROVENANCE BOUNDARY       PASS / KNOWN
```

The test is not "does it stop looking like the donor?"

The test becomes:

> **Does it behave and compose like the selected donor where the contract requires fidelity, while speaking, meaning, proving, and identifying itself as the target?**

### For R4

Authorization and provenance become explicit gate conditions.

---

## 9. Framework learning from VTKALL × Dayos

This case establishes a strong cross-case candidate:

> **Ink-VK is not inherently an anti-replication framework. It is a controlled source-to-soul transformation framework whose acceptable donor fidelity must be declared explicitly.**

This learning is currently:

```text
CROSS-CASE CANDIDATE
```

It should not be frozen as foundation baseline until tested against at least one additional migration case.
