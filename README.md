# Project Ink-VK

> **Chinese Method finds the DNA. Ink makes it belong. VK verifies the transformation.**

Project Ink-VK is a controlled source-to-soul engineering framework for discovering useful existing implementations and experiences, extracting reusable intelligence, and transforming that intelligence around the identity, truth, operations, constraints, and intended experience of a specific target.

## Current state

```text
STEP 0 — FOUNDATION     ✅ FROZEN v1.0
```

Ink-VK is now operationally complete enough to open a new campaign on another entity without reconstructing the method from chat history.

Validation will continue to accumulate across new cases, target domains, replication modes, and post-BUILD evidence. Those learnings become versioned framework deltas rather than reopening Foundation by default.

## Canonical doctrine

```text
DRONE  → recover the terrain
KNIFE  → expose useful anatomy
INK    → re-author around target Soul and truth
UTV    → migrate in controlled slices
VK     → prove fidelity and ownership
MEMORY → improve the next campaign
```

Ink-VK does not ask:

> How do we make the target look like the donor?

It asks:

> **What useful intelligence did the donor prove, what does the target actually need, what fidelity is explicitly authorized, and how must that intelligence be re-authored so the result belongs to the target without violating truth, provenance, or non-regression?**

## Replication modes

Ink-VK does not assume one correct distance from the donor.

```text
R1 — Pattern Transfer
R2 — Structural Transposition
R3 — Experiential Soul Transposition
R4 — Authorized Implementation Reuse overlay
```

Direct code, asset, model, or copy reuse is never inferred from visual similarity. R4 requires rights/provenance evidence.

## Canonical proving case

`VTKALL × Dayos` is the first canonical proving case.

It exercised the framework from target recovery through Design Freeze / PLAN Readiness and exposed the foundation rules for:

- explicit replication fidelity;
- Target Truth;
- Target Non-Regression;
- Content Capacity;
- Donor Job Decomposition;
- Institutional Evidence Scope;
- Interaction Dependency Truth;
- Cross-Route Coherence;
- implementation-safe unknowns;
- concept-frame vs frozen-blueprint authority.

The case still has not completed the real PLAN → BUILD → post-BUILD validation stack. That future evidence may refine v1.x without invalidating Foundation v1.0 automatically.

## Knowledge rules

- Meaningful project knowledge must not live only in chat.
- Material iterations are persisted as new versioned artifacts.
- Frozen baselines are historical records and are not silently rewritten.
- Valid older versions remain history; they are not automatically deprecated.
- `deprecated/` is reserved for explicitly invalidated, abandoned, unsafe, or superseded directions that should no longer guide active work.
- Sources and references retain provenance.
- A recovered source is not automatically an adopted solution.
- Ink-VK distinguishes what was **observed**, **inferred**, **decided**, **adapted**, **replaced**, **deferred**, and **created new**.
- `main` is not modified directly by agent experimentation; work proceeds on explicit branches/PRs under human review.

## Safety and legitimacy boundary

Ink-VK is intended for legitimate reuse, study, adaptation, reimplementation, migration, and client-specific differentiation. Source licensing, provenance, ownership, privacy, security, authorization, and confidentiality remain part of the transformation contract.

The Blade Runner / Voight-Kampff mythology is the project's conceptual identity. It does not redefine Ink-VK as an anti-bot, anti-abuse, security-evasion, or access-control bypass system.
